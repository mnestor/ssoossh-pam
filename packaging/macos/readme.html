What is installed

/usr/local/lib/pam/pam_ssoossh.so
/usr/local/share/man/man8/pam_ssoossh.8
/usr/local/share/man/man5/pam_ssoossh-ca.5, pam_ssoossh-principals.5
/usr/local/share/doc/pam_ssoossh/     BUILDINFO, LICENSE, examples/

The module lives under /usr/local because /usr/lib/pam, where macOS keeps its own modules, is protected by System Integrity Protection. A pam.d line therefore names it by absolute path.

Enabling it for sudo

macOS reads /etc/pam.d/sudo_local from sudo and leaves that file alone across OS updates. Create it from Apple's template if it does not exist, then add the module above the Touch ID line:

sudo cp /etc/pam.d/sudo_local.template /etc/pam.d/sudo_local

auth  sufficient  /usr/local/lib/pam/pam_ssoossh.so server=https://ssoossh.example.com trusted-ca-file=/etc/ssoossh/ca.pub ssh-only
auth  sufficient  pam_tid.so

With ssh-only, someone at the keyboard keeps Touch ID and someone who arrived over SSH gets the browser flow. Keep a second root shell open while you test. man pam_ssoossh describes every option; /usr/local/share/doc/pam_ssoossh/examples/pam.d/sudo_local is this stanza with its reasoning.

The server it was tested against

This build was qualified against ssoosshd @COMPAT@. The module and the server are released separately, so the version above need not match your server's. The module names the release it was tested against in the line it logs on every authentication, and /usr/local/share/doc/pam_ssoossh/BUILDINFO records it too.

Removing it

Delete the pam.d line first, then the files listed above, and forget the receipt with sudo pkgutil --forget @IDENTIFIER@.
